# 5. Web vs iOS — что переносится

| Приём iOS | На вебе | Комментарий |
|---|---|---|
| SF Pro | `system-ui` стек или свой шрифт | Файлы SF Pro на сайт не встраивать |
| SF Symbols | Свои SVG-иконки (1.2–1.5px линия) | Лицензия SF Symbols — только приложения на платформах Apple |
| Dynamic Type | `rem` + `clamp()` | Не фиксировать всё в px |
| Tab bar | Нижняя панель только в веб-приложениях; на сайте — хедер | На маркетинговом сайте tab bar выглядит чужим |
| Large Title | Крупный H1, хедер ужимается при скролле | |
| Sheet со свайпом | `<dialog>` снизу на мобиле, по центру на десктопе | Свайп — бонус, кнопка закрытия обязательна |
| Swipe-действия | Видимые кнопки/меню | На вебе свайпы никто не ищет |
| Haptics | Нет | Заменять микроанимацией нажатия |
| Blur-материалы | `backdrop-filter: blur()` | Проверять производительность на слабых Android |
| Safe area | `env(safe-area-inset-*)` | Нужен `viewport-fit=cover` |
| Hover | Есть на вебе, нет на iOS | Ничего важного не прятать за hover |
| Скругления | `border-radius` | В NUR и Rahma — 0 |

## Что делает apple.com и стоит повторять
- Одна мысль на экран, огромный заголовок, короткий подзаголовок, две ссылки-действия.
- Чередование светлых (`#FFF`/`#F5F5F7`) и тёмных (`#000`) секций.
- Продукт — главный визуал, текст его подписывает.
- Анимации завязаны на скролл, но страница читается и без них.

## Что не переносить
- Имитацию нативных iOS-контролов на сайте (переключатели-«пилюли» вместо чекбоксов в обычной форме).
- Жесты без видимой альтернативы.
- Шрифт и иконки Apple.
