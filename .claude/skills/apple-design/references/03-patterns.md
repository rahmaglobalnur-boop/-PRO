# 3. Patterns — формы, списки, модалки, состояния

## Формы
- Спрашивать минимум. Каждое поле — лишний шанс, что человек уйдёт.
- Группировать по смыслу (контакты / доставка / оплата), по 3–5 полей в группе.
- Автозаполнение и правильные `autocomplete` важнее красивых полей.
- Кнопка отправки неактивна, пока нет обязательного; но объясни, чего не хватает.
- После отправки — ясный экран успеха. Это пик опыта (Peak-End), он должен быть самым чистым.

## Списки
- Строка: главный текст слева, вторичный под ним серым, действие/шеврон справа.
- Сгруппированные списки (inset grouped) — для настроек; простые — для контента.
- Свайп-действия на телефоне дублируются видимым способом (меню, кнопка).
- Длинные списки: поиск сверху, алфавитный индекс или фильтры.

## Модальные окна
| Тип | Когда |
|---|---|
| Alert | Важное решение или ошибка. 1–2 кнопки, максимум 3 |
| Action sheet / меню | Выбор из нескольких действий |
| Sheet | Отдельная задача (новое письмо, фильтры). Закрывается свайпом вниз |
| Full-screen | Длинная задача с несколькими шагами |

- Модалка прерывает. Если можно без неё — делай без неё.
- В alert кнопка «Отмена» есть всегда; разрушительная — красная.
- На вебе: `<dialog>`, фокус внутрь при открытии, Esc закрывает, фокус возвращается назад.

## Состояния (проектировать каждое)
| Состояние | Что показать |
|---|---|
| Пусто | Что здесь будет и одно действие, чтобы начать |
| Загрузка | Скелетон по форме контента; спиннер — только для коротких ожиданий |
| Ошибка | Что случилось простыми словами + «Повторить» |
| Частично | Показать то, что есть, отметить недостающее |
| Успех | Короткое подтверждение, без модалки, если не нужно |
| Офлайн | Что доступно без сети |
